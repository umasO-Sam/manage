# 見積番号（注番）の付与規約

社内規約の書き起こし（2026-08-17、規約図より）。採番画面と `QuoteNumberAllocator` は
この規約に従う。**規約と実装が食い違ったら、この文書を先に直してから実装を直す。**

## 形

```
XX 999 - Y 99 (Z)(9)(9) (Z)(9)(9) (Z)(9)(9)
└┬┘ └┬┘   └┬┘└┬┘ └────┬────┘
 │   │     │  │       └ 補足区分（最大3段）
 │   │     │  └ 見積通番（2桁）
 │   │     └ 見積区分
 │   └ 見積単位（3桁表示。4桁なら4桁表示）
 └ 客先番号（1桁なら1桁表示、3桁なら3桁表示）
```

ハイフンより後ろ（`Y99…`）が**原価集計単位**。客先番号から見積通番までが**経理集計範囲**。

| 区分 | 意味 |
|---|---|
| **N** | 通常（集計単位） |
| **F** | フェイク（ダミー見積） |

| 補足区分 | 意味 | 原価の集約 |
|---|---|---|
| **T** | 追加 | 元のN99に**集約する** |
| **K** | 改造 | 元のN99に集約しない |
| **S** | 修理 | 元のN99に集約しない |
| **B** | 部品 | 元のN99に集約しない |
| **H** | 変更 | 営業担当者の管理用 |

## 例

| 場面 | 見積番号 |
|---|---|
| 装置番号999の新規見積、1回目 | `N999-N01` |
| その変更2回目（同時提出で比較してもらうときも H01, H02… と採番） | `N999-N01H02` |
| 追加見積、合算する場合（変更するときは番号を繰り上げる） | `N999-N01T01` → `N999-N01T02` |
| 改造1回目（新規見積） | `N999-N01K01` |
| **改造1回目の部品**（新規見積） | `N999-N01K01B01` |

**補足区分は多段になる**（`N01K01B01`）。B は N の後ろだけでなく K の後ろにも付くため、
採番時に選ぶ「元の見積番号」は `N01` のような通常番号とは限らない。

### 請求が分かれる場合

設計・製造・現地工事で請求が分かれるなら `N999-N01` `N999-N02` `N999-N03` と分ける。
**前受け金をもらう場合は全て N01**。この内、工事1と工事3だけ受注して値引きが発生する等の
場合は `N999-N04` として取り直す。

### T（追加）の使いどころ

- `XX100-N01` を受注して**作業中に**仕様変更などで追加見積を出す場合に使う
- **過去に完了した案件に T は使わない**
- 過去装置の前後装置を追加するような場合は、**N99 を繰り上げていく**

### B（部品）

部品のみ販売のときに使う。

## 実装との対応

- 採番の計算は `app/Services/QuoteNumberAllocator.php` の1箇所に集約している
- 案件種別と補足区分の対応は `QuoteNumberAllocator::MODES`
- 改造(K)・修理(S)・部品(B)は、対象の過去装置が無ければ**普通の新規案件(N)として採る**
  （`OPTIONAL_BASE_MODES`）。ただし**見積単位を指定しているときは倒さない** —
  特定の装置を指しておきながら客先の老番+1（別の装置）を発番する事故になるため
- 「TL091」のように**通番まで入れて検索すると、その通番が採番の見積単位になる**。
  補足区分を選ぶと、その見積単位に実在する注番が「元の見積番号」の候補として並ぶ
  （1つだけなら自動で決まる。1つも読み取れない旧形式だけの見積単位は N01 を補い、画面で注意喚起する）
- 過去の台帳には規約に沿わない表記が残っている（`TL02-B01N02` のように B と N が逆。
  本番で2件）。採番の計算は前から読むため、**逆順の行は元番号として認識されない**。
  同じ装置に部品を採ると通番が振り直しになるので、見つけたら台帳側を直す
